# DCA Backtest — академічне дослідження

Система бектесту стратегії **Dollar Cost Averaging (DCA)** з алгоритмічним take-profit продажем. Проєкт є академічним дослідженням: порівнюється класичне регулярне інвестування з підходом, де часткові продажі керуються технічними індикаторами та моделлю машинного навчання.

Матеріали дослідження (пояснювальна записка, література, інструкції) зібрані в каталозі [`docs/`](docs/).

> **Важливо:** застосунок призначений для освітніх і дослідницьких цілей і **не є фінансовою порадою**.

---

## Що досліджується

Класичний DCA купує актив фіксованою сумою з фіксованою частотою і тримає позицію. У цьому проєкті перевіряється гібрид:

1. **Регулярні покупки** (DCA) за розкладом.
2. **Take-profit продаж** частини позиції, коли виконуються умови прибутку та сигнали модулів рішень.
3. **Докупка на просіданні** з накопиченого `extra_cash` (якщо ціна нижче порогу відносно середньої собівартості).
4. **Cooldown** після продажу, щоб уникнути серії зайвих угод.

Мета — оцінити, чи покращує керований take-profit метрики (прибуток та ризики) порівняно з buy-and-hold DCA.

## Як працює

### Потік даних і симуляції

```
ціни (Yahoo Finance / CSV)
        >>>
BacktestDCA (app.py)
        >>>
історія + метрики
        >>>
графік / веб-UI (ploter.py, web.py)
```

1. Завантажуються денні ціни (`Close`).
2. На датах згідно частоти (`W-MON`, `WOM-1MON`, `D`) виконується покупка на `buy_amount` (з урахуванням комісії `fee`).
3. Щодня перевіряється умова take-profit: ліквідність, warmup-ліміт, `minimum_profit`, cooldown.
4. Якщо умова часу виконана — викликаються модулі рішень; обирається **найагресивніший** сигнал (найбільша частка продажу).
5. Після продажу фіксуються `Profit`, `Returns`, `Trigger_msg`, оновлюється cooldown.
6. Наприкінці рахуються метрики: витрачені кошти, вартість портфеля, MDD, тощо.

### Модулі рішень (`sell_decision/`)

| Модуль | Тип | Ідея |
|--------|-----|------|
| MA200 | major | ціна значно вище 200-денної середньої |
| ROC | major | сильний Rate of Change |
| PPO | major | сигнал Percentage Price Oscillator |
| Bollinger Bands | minor | вихід за верхню межу |
| RSI | minor | перекупленість |
| Portfolio limit | full | портфель перевищив ліміт років інвестицій |
| Random Forest (`SellModel`) | major | прогноз ризику падіння на горизонті ~90 днів |

Можна зафіксувати частку продажу вручну (`manual_sell_fraction`) або вимкнути продаж (`enable_sell: false`) для baseline buy-and-hold.

Параметри за замовчуванням — [`configs/variables.yaml`](configs/variables.yaml).

## Локальний запуск

### Вимоги

- Python 3.10+
- залежності з `requirements.txt`

### Встановлення

```bash
git clone https://github.com/Familenko/DCA.git
cd DCA
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Веб-застосунок

```bash
python web.py
```

(скрипт сам перезапустить себе через Streamlit, якщо запущений без контексту Streamlit.)

За замовчуванням UI доступний на [http://localhost:8501](http://localhost:8501).

У сайдбарі оберіть актив, період, параметри стратегії та натисніть **Run backtest**. Дані для веб-UI підтягуються з Yahoo Finance.

Якщо порт 8501 зайнятий:

```bash
lsof -ti tcp:8501 | xargs kill -9
```

### Програмний запуск бектесту

```python
from app import BacktestDCA

bt = BacktestDCA(
    target="BTC",
    prices=prices_series,
    strategy={"buy_amount": 10, "freq": "W-MON"},
)
history, metrics = bt.run()
```

### Вигрузка даних
```bash
python loader.py
```
